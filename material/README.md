# 物料与工具库

记录**手上实际拥有**的元器件、模块、连接器、线材与工具：有没有、有几只、从哪批来、手册放哪。  
器件怎么用（针序、尺寸、接线）查 [`devices/`](../devices/README.md)。两边用同一个 `id`。

本文件是 **material 的操作说明**：根目录有什么、每个型号怎么放、怎么新增、怎么删除、改完要动哪些文件。

## 这个库怎么用

**画原理图 / PCB 之前必须先查本库。** 三条硬规则：

1. **优先复用库内已有器件**，不够再补购。设计里出现库外规格，要在文档里显式写明「需补购」。
2. **元件全部自行采购、手工焊接，不走立创 PCBA。** 所以 C 编号只用于在嘉立创 EDA 里
   取正确的**符号与封装**，不用于下单。唯一的判定标准是**封装尺寸与手上实物一致**。
3. **尺寸未确认的机械件不许猜封装。** 开关、连接器、保险丝座、蜂鸣器、模块座同名不同厂，
   脚距可能不同。凡列在 [待补资料](pending.md) 里的对象，
   原理图可以画，**PCB 封装不可定稿**。

## 和 `devices/` 怎么分工

| | `material/` | `devices/` |
|---|---|---|
| 记什么 | 买了什么、有几只、状态、分立件自己的芯片手册 | 这块板/这个模块怎么用 |
| 主键 | `id`（小写，以后不改） | 同一个 `id` |
| 模块 | `modules/<id>/` 只留库存卡，用 `devices_id` 跳转 | 针序、尺寸、PDF、例程 |
| 电阻/电容/IC/钳子 | 本库是主档案，手册放在该型号自己的文件夹 | 不建 |

不要把同一份 PDF 在两边各放一份。模块手册只在 `devices/`；PESD1CAN 这类分立件手册只在 `material/pcb/<id>/`。

## 根目录有什么

```text
material/
  README.md         ← 本说明
  catalog.yaml      ← 总目录（检索第一份必读）
  pending.md        ← 「不许猜封装」汇总，来自各卡片的 pending:
  pending-specs.md  ← 旧路径跳转，不要往里写新内容
  pcb/              ← 可焊到自制 PCB 的分立件
  connectors/       ← 排针排母、XH/PH/XA、端子、保险丝座、XT
  wiring/           ← 导线、成品线、热缩、编织、管型端子
  modules/          ← 成品模块的库存卡
  mechanical/       ← 电机、轮、联轴器、舵机
  tools/            ← 烧录、压接、装配、标签机
  purchases/        ← 哪一批买了什么（不拆到型号里）
  _inbox/           ← 暂时无法可靠归属的原始资料；隔离区，不是设计依据
  inventory/        ← 旧总表的跳转，不要往里写新内容
```

不要在 `material/` 根下再放散文件（PDF、图、压缩包）。手册一律进对应型号文件夹。

`_inbox/` 只用于**暂时无法确认具体型号/归属**的原始资料。放进 _inbox 的文件必须有说明，设计检索时不得当作已验证规格或可定稿封装；确认身份后应迁入正式物料目录并清空对应 inbox 项。  
不要再往 `inventory/` 里记规格——那五份只是给旧链接留的跳板。

| 根文件 | 职责 |
|---|---|
| [`catalog.yaml`](catalog.yaml) | 全库过滤：`id`、`aliases`、`kind`、`qty`、`status`、`path`。没写进这里的文件夹 = 还没登记。 |
| [`pending.md`](pending.md) | 仍缺尺寸/数量/参数的汇总。闭环后从对应 `item.yaml` 和本表两边删。 |
| `README.md` | 怎么维护；文末分类入口必须能点到六个子目录。 |

## 每个物料文件夹

已登记物料的根上必须有：

| 文件 | 作用 |
|---|---|
| `item.yaml` | 结构化卡片：数量、状态、封装、C 编号、待补、文件指针。没确认的字段不写，禁止按同名商品猜封装。 |
| `INDEX.md` | 阅读入口：一眼看到有几只、警告、手册在哪。 |

`id` 是主键：小写、型号或规格、无空格。例如 `pesd1can`、`r-0805-10k`、`xh254`。文件夹名 = `id`。

子目录 **按文件内容** 建，缺的不要空建：

| 子目录 | 放什么 | 不放什么 |
|---|---|---|
| `datasheets/` | 该型号的芯片/商品手册 | 别的型号、混合资料包 |
| `images/` | 该型号实物照片（封装、丝印） | 购物海报、别的料 |
| `mechanical/` | 底面尺寸图、脚距 | 原理图 |
| `docs/` | 本库写的短说明 | 商家原 PDF |

样板：[`pcb/pesd1can/`](pcb/pesd1can/INDEX.md)（有手册）；[`modules/p03b/`](modules/p03b/INDEX.md)（库存卡，手册在 devices）。

**系列变体**：只是针数/颜色/长度不同、会共用同一份尺寸图的，放在**同一个**文件夹，写在 `item.yaml` 的 `variants:`（如 `xh254` 的 2–8P）。互不通用的型号分开建（如 XT30 线端 vs PCB 焊板）。

## 检索（人与 AI 相同）

1. 读 `catalog.yaml`，按 `id` / `aliases` / `kind` / `category` 选出物料。
2. 打开该目录的 `item.yaml` 和 `INDEX.md`。
3. 需要手册、脚距图时，再打开卡片 `files:` 里列出的 PDF。
4. 若卡片有 `devices_id`：针序和模块手册去 `devices/`，不要在 material 里找 PDF。

不要从根目录漫游文件夹名来猜。选型时也可以先打开分类 README（下面「分类入口」），那是给人扫的表。

## 新增物料

在对应**分类目录**下新建一个文件夹，不要丢在 `material/` 根上，也不要塞进别的型号里。

1. **定 `id` 和分类**  
   查 `catalog.yaml` 有没有同 id。小写、可检索、以后不改。别名（中文商品名、C 编号、SKU）写进 `aliases`。  
   分类：`pcb` / `connectors` / `wiring` / `modules` / `mechanical` / `tools`。  
   已有器件档案的模块：`id` 必须与 `devices/` 相同。

2. **建文件夹**  
   `material/<分类>/<id>/`。不要预建空的 `datasheets/` `images/`。

3. **看每一份原件再归档**  
   用户丢进来的图/PDF，按内容放进上表对应子目录，并改成能看懂的文件名。  
   同一张图：有清晰 PDF 就不留糊截图。  
   混合包：只抽出**确定属于本型号**的文件，然后把混合包和无关内容删掉。  
   模块的手册放 `devices/`，这边不要复制。

4. **写 `item.yaml`**  
   至少：`id`、`name`、`kind`、`qty`（或 `qty_label`）、`status`。  
   分立件补 `package`、`lcsc`（有的话）、`lcsc_trust`（`official` / `equivalent`）。  
   模块补 `devices_id` + `devices_entry`。  
   封装还不能定稿的，把原因写进 `pending:`（`footprint` / `vmax` / `qty` 等）。

5. **写 `INDEX.md`**  
   开头标明 id 和卡片链接。有警告、手册、待补就写上。

6. **登记四处（缺一不可）**  
   - `catalog.yaml` 的 `items:` 追加一条（`path` 用 `<分类>/<id>`）。  
   - 该分类的 `README.md` 表追加一行。  
   - 若有 `pending:`：同步改 [`pending.md`](pending.md)。  
   - 若这是已有 `devices/` 档案的模块：devices 卡片不用改数量；只保证 `id` 一致。

7. **收尾**  
   删空文件夹。到货后状态从 `已购-在途` / `已购-待取` 改成 `现有` 或 `已购`。  
   同一型号不新建第二份文件夹，只改数量与状态。

未做完第 6 步的，不算登记完成；别人和 AI 都不应把它当已入库。

## 删除物料

删除是「连同编目一起拿掉」，不是只删文件夹。

1. 在 `catalog.yaml` 里删掉该 `id` 整条。
2. 在对应分类 `README.md` 表删掉该行。
3. 在 `pending.md` 删掉该行（如果有）。
4. 全库搜该 `id`、旧路径（`inventory/*.md`、项目原理图、`component_mapping.csv`），改掉或标明已撤。
5. 若 `devices/` 有同一 `id`：器件档案可以留（怎么用还在），但库存事实没了，要在 devices 的 INDEX 里不要再暗示「手上一定有」。
6. 删除整个物料文件夹（含子目录）。不要留下空的 `datasheets/`。

只删该型号里的个别无关文件（过时手册、购物图）走下面「维护」，不必走整项删除。

## 维护已有物料

| 要做的事 | 做法 |
|---|---|
| 多了一份手册 / 一张尺寸图 | 看内容放进该型号文件夹；新类目有文件再建模。更新 `INDEX.md` 和 `item.yaml` 的 `files:`。 |
| 到货 / 用掉 / 清点 | 只改 `qty` 和 `status`，同步 `catalog.yaml` 的 `qty`/`status` 和分类表。 |
| 同型号又买了一批 | **不新建文件夹**，把数量加上，来源可在 `purchases/` 记一批次。 |
| 拿到待定件的尺寸图 | 关键尺寸写进 `item.yaml`，从 `pending:` 和 `pending.md` 删除该行。 |
| 模块补了 devices 档案 | 物料卡改成 `devices_id` + 指针，删掉这边复制的规格/PDF。 |
| 发现数量或 C 编号写错 | 改 `item.yaml`、`INDEX.md`、`catalog.yaml`、分类表，四处一致。 |
| 混进别的型号 | 抽出本型号文件后 **整包删除**。 |
| 改文件夹名 / 改 `id` | 同时改：卡片、INDEX、catalog、分类表、pending、devices 里的对应 id。尽量不要改 id。 |

改完后看一眼上层：`catalog.yaml`、分类 README、`pending.md`、以及控制仓 [`README.md`](../README.md)（文档层级联动）。

库存状态只分这些档：`现有` / `已购` / `已购-在途` / `已购-待取`。  
**不记**价格、商家链接、订单号、购买日期、物流单号——批次追溯只写「哪一批有过什么」，见 [`purchases/`](purchases/README.md)。

## 设计时最常踩的三个坑

| 坑 | 事实 |
|---|---|
| 电阻阻值不在库里 | 只有 **11 个阻值**：0 / 10 / 100 / 120 / 220 / 330 Ω，1k / 4.7k / 10k / 47k / 100k |
| 用了 2×N 排母 | **双排排母已补货，数量待录**（`header-2xn-female`）。没录数量之前，退路仍是两条 1×20P 单排母并排 |
| 用了 XH2.54-7P 或汽车插片保险丝座 | XH **7P 已补货、数量待录**；保险丝只有 **5×20 玻璃管**方案，没有插片座 |
