# private/ —— 私有库

**单个引入的东西 + 本项目自建的东西**，都在这里。判据是**引入方式**：
挑一两个文件进来 → 私有库；整套克隆进来 → [`../thirdparty/`](../thirdparty/)。

```
private/
├── vibecoder.pretty/     封装（库键 vibecoder:）
├── vibecoder.kicad_sym   符号（库键 vibecoder:）
├── vibecoder.3dshapes/   3D 模型（STEP）
└── LICENSES/             上游许可证原文
```

**D2 的 3D 已于 2026-08-29 解决，来源是用户自己找到的。** 前情：官方 `AAA3528ESGCT`
封装引用的 `LED_SMD.3dshapes/LED_Kingbright_AAA3528ESGCT.step` **根本不存在**——
本机装的该库只有 38 个模型对 99 个封装，上游 `kicad-packages3D` 同目录也只有 39 个文件，
都没有它。最近的官方本体 Wuerth `150141M173100`（3.2×2.8）比实物 **X 向小 0.3 mm**，
偏小会**低报**间隙，是危险方向，所以宁可空着也不借用。

**chatgpt-web 独立复核确认了这个结论**，并给出了更准确的说法：这是一个
**dangling 3D reference**——封装的引用存在，但模型从未随官方 packages3D 发布，
不是本机安装缺文件。他同时承认上一轮是把"封装里有 `(model ...)` 引用"
错当成了"官方 3D 包里一定存在该文件"。

**这一条的教训：宁可空着等一个对的，也不要借一个偏小的顶上。** 空了不到一天，
用户就找来了尺寸完全正确的模型；要是当时借了 Wuerth 顶上，外壳大概率会照着
3.2 开孔，而且没人会再回头查。`TALK-vibecoder-20260829-01` 据此关闭。

⚠ 按 chatgpt-web 的提醒记一条：这个模型**只用于机械外包络**。
D2 的 symbol / footprint / 针序一律保持项目自建版本，
**绝不能换成 Kingbright 的电气定义**——用户这颗是 `1=R阴 2=公共阳 3=G阴 4=B阴`。

## 维护规则

1. **新增文件必须同时在上面的来源表加一行**，四列都要填：文件、来历、许可证、回读复核结论。
2. **带许可证的，原文放 [`LICENSES/`](LICENSES/)**，文件名标明是谁的、什么许可证。
3. **引入前先回读复核**，与厂家图/实测值逐项比对。对不上就不要引入。
4. **上游更新时先比对再替换**，比对结论更新进来源表。
5. **3D 只服务于 enclosure / collision / actuator 定位。** 模型与厂家图冲突时**以厂家图为准**，
   并在表里写明差异（本目录已有两条这样的差异：SS12D 的外罩耳朵、D2 的偏小 0.3 mm）。
6. **不要在这里放整套库。** 那属于 [`../thirdparty/`](../thirdparty/)。
7. **一个封装可以挂多个 3D 模型**，用来一次显示整套装配（座 + 插上去的模块）。
   官方件走 `${KICAD10_3DMODEL_DIR}`，**不要复制进私有库**；只有自建和单个引入的才进这里。
   `INMP441_Module_2x3_P2.54mm` 就是这么做的：两条官方排母 + 一个私有库的模块本体。
8. **3D 变换写完必须渲染验证，不许靠脑补。** 跑
   `python ../../tools/render_footprint_3d.py <封装.kicad_mod>`，看俯视图引脚有没有落在
   焊盘上、侧视图本体是不是平贴板面。坐标系反直觉：`offset.x` 是 **+**Δ板X，
   `offset.y` 是 **−**Δ板Y，`offset.z` 是 **+**Δ板Z，`rotate` 的角度还会被 KiCad **取负**。
   TTC 编码器就是这么栽的——`offset(0,0,0.76)` 看着合理，实际把本体沉进板子 3.2 mm。
