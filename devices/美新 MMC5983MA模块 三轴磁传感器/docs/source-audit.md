## 2. 从图片可以确认什么

高置信度信息：

- 模块 PCB 标注尺寸约 15.00 mm × 10.00 mm。
- 接口为 VIN、GND、SDA、SCL 四针。
- PCB 设计预留传感器 `U2` 和若干电源、上拉、去耦元件位置。
- 图片绘有三轴方向参考。

不能从图片确认：

- VIN 的允许电压范围。
- 是否安装稳压器、其型号和压差。
- SDA/SCL 上拉到哪一路电源、实际阻值是多少。
- U2 是否确实为 MMC5983MA，而不是兼容封装器件。
- CAP 脚的 SET/RESET 储能电容是否达到官方要求的 10 µF low-ESR。
- 图片中的轴向是否与拿到的实物批次完全一致。

因此文档把 3.3 V 作为安全默认，并要求用 Product ID 和实物测量完成身份确认。

## 5. 开源实现抽查结论

SparkFun v1.1.5 与官方数据手册一致的关键点：

- I²C 地址 `0x30`，Product ID `0x30`。
- 18 位拼接使用 `0x00–0x06` 七字节。
- 零场中心使用 131072，量程按 ±8 G 换算。
- 软件复位后等待 15 ms。
- 控制寄存器用 RAM shadow 管理，避免 read-modify-write。
- 支持 SET、RESET、自动 SR、周期 SET、连续频率和通道禁止。
- 所有等待循环加入超时，避免器件/总线故障导致永久卡死。

需要针对当前模块修改的部分：

- SparkFun 连续测量例程使用 INT；当前四针模块没有 INT，需改为轮询。
- SparkFun SPI 示例不能用于当前四针模块。
- SparkFun Qwiic 板的电源和电平设计不能证明淘宝模块支持相同输入范围。
- SparkFun 航向公式与其板卡轴向绑定，当前模块需重新确认轴映射。

## 6. 未归档的候选源码

- `VincentChantreau/mmc5983ma`：通用 C 驱动，GPL-3.0，作者 README 明确标注 WIP、功能未完整；仅列为在线对照，不作为推荐基线。
- `Ahreo/MMC5983MA-Driver`：基于 STM32H723 的 C++ 实现，但仓库没有明确许可证；未复制到本地。
- `kriswiner/MMC5983MA`：较早的多传感器 Arduino/AHRS 示例，适合算法参考，但不是独立、当前维护的通用驱动；未复制到本地。

这样可以避免在型号目录中堆积授权不明确、未完成或与其他传感器强耦合的源码。

## 7. 资料缺口

目前仍缺少当前淘宝模块本身的：

- 原理图/BOM/Gerber。
- 正反面高清实物照片。
- 商家明确的 VIN 和 I²C 电平规格。
- U1、U2 和 R1/R2 实际器件/阻值。

拿到实物后，优先补拍正反面和芯片丝印；若后续找到卖家原理图，应保留原文件并在本审计中追加来源，不要用 SparkFun 板卡原理图替代当前模块。
